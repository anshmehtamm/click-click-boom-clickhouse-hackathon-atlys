01 · Grounded, not guessed

How do we ground schema generation?

An agent reasoning about a schema only from what it wrote down is reasoning about vibes, not the table. Two harnesses, used together.

Staging Harness created once

A real ClickHouse staging area, provisioned once up front — every proposed schema is actually built and loaded with real data here before anyone trusts it.

Proposal v1 Proposal v2 Proposal v3
→ Staging tables → data quality checked
Use case

Every revision is tested for data quality here — not just re-argued in text.

Perf Harness

"This ORDER BY will be faster" is a guess, not evidence — so the winner is measured, never asserted.

Staging tables → time candidates A · B · C → winner + worst flagged
Use case

Times every candidate against staged data, flagging the agent if one is clearly the worst.
